# System requirements engineering

Status: proposed derived baseline, 30 September 2026. System requirements (SR) translate Customer-User-Stories (CUS) into verifiable obligations. The SR layer covers every applicable perspective, including legal, engineering, running environments, architecture, and data security; the current draft does not yet establish complete coverage. These statements do not select a technology stack. The [WP01 requirements package](wp01-requirements-package.md) proposes the open contracts; official FIT evidence, limits, interfaces, and quality thresholds require approval before a release baseline is frozen.

For each CUS, the System Architect records which perspectives apply, the derived SR IDs, evidence or decision sources, and open gaps. Assess legal and regulatory duties, engineering behavior, runtime and deployment environments, architecture and interfaces, data protection and security, accessibility, operations, and any domain-specific concern. Mark a perspective not applicable only with a reason. Do not invent legal obligations or claim completeness from the current draft.

Each current SR traces to one CUS; the registry permits multiple CUS parents for a cross-cutting SR. A work package may implement several requirements. Pull request reviews must list affected CUS and SR IDs and verification evidence; modifications to public contracts need an explicit decision record. Legal and other cross-cutting requirements need explicit assessment and approval before claiming the SR baseline is complete.
